## Збереження

Архів `stadion_oster_reference_pack_2026-08-20.zip`, який раніше лежав у цій папці, видалено з `main`: payload був невалідним ZIP і водночас був закомічений як звичайний binary при активному Git LFS правилі `*.zip`, через що локальна копія постійно показувала файл як змінений навіть після Discard Changes.

> Integrity status: `RESTORE_REQUIRED`. Canonical photo pack треба повторно зібрати з 17 оригінальних референсів, перевірити `unzip -t`, а вже потім додавати назад коректним LFS-способом. До цього моменту не створювати фальшивий або порожній ZIP-заповнювач.

Оригінальні кадри не слід замінювати випадковими веб-зображеннями. Цей набір має вищий пріоритет за старі provisional placement-коментарі в коді.

## Правило використання

- Карти 16–17 визначають macro-placement і взаємне положення локацій.
- Фото 1–15 визначають внутрішню композицію site block, периметр, рослинність, спортивні елементи та прилеглу забудову.
- Новіші фото визначають актуальний стан, якщо вони суперечать старішим.
- Старі фото залишаються корисними для сталих орієнтирів: дерева, межі ділянки, житлова забудова, стежки, дальні силуети.
- Жоден кадр не можна трактувати як доказ GPS-координат без карти/geo-anchor.

## Постійне правило проекту

Якщо користувач передає фото спеціально для створення 3D-моделі або локації, ці фото потрібно зберігати в репозиторії як reference pack навіть без окремої команди «збережи». Для звичайних скріншотів багів/тестів збереження в корінь не є автоматичним, якщо користувач цього не просив.
