# OSTER CONFLICT — LOCAL WORKFLOW

Цей файл фіксує фактичний локальний спосіб роботи користувача. Перед будь-якими інструкціями щодо запуску, перемикання гілок або оновлення локальної копії спочатку враховувати цей workflow.

## Постійні інструменти користувача

- GitHub Desktop — основний спосіб роботи з гілками, commit, push, fetch/pull.
- `START_HERE.cmd` у корені репозиторію — основний локальний launcher/консоль для build/test/playtest.
- Windows CMD/PowerShell використовувати лише коли GitHub Desktop або `START_HERE.cmd` не можуть виконати потрібну дію.

## Правило для відповідей

Не давати довгі набори `git fetch`, `git reset --hard`, `git lfs pull` та інших CLI-команд, якщо те саме можна безпечніше зробити через GitHub Desktop.

При наявності незакомічених локальних змін не рекомендувати `git reset --hard` до їх збереження. Спочатку commit у поточну робочу гілку та push, потім перемикання на `main`.

## Типова схема оновлення до актуального main

1. У GitHub Desktop зберегти поточні зміни commit-ом у поточній робочій гілці.
2. `Push origin`.
3. Через `Current branch` перейти на `main`.
4. `Fetch origin`, потім `Pull origin`, якщо доступно.
5. Запустити `START_HERE.cmd` з кореня репозиторію.

## Канонічні режими запуску

- `START_HERE.cmd` пункт **5** — основний playtest актуальної гри. Він запускає **NORMAL GAME / frontend**, після чого `START / LOCAL GAME` відкриває звичайний TEAM-match. Саме цей режим використовувати для оцінки зброї, освітлення, HUD, меню та реального gameplay.
- `START_HERE.cmd` пункт **9** — окремий **Sandbox / Test Range diagnostic**. Він потрібен тільки для технічної перевірки географії/локацій і не є репрезентативним виглядом звичайної гри.
- Не підміняти пункт 5 sandbox-маршрутом. Це вже спричиняло хибне враження, що запущена стара версія гри.

## Важливо

Якщо `START_HERE.cmd` показує старий R11/R13 launcher, спочатку перевірити, на якій локальній гілці відкритий GitHub Desktop. Не робити висновок про стан `main` лише за BAT-файлом з іншої гілки.

Якщо картинка раптово стає пересвіченою або зброя повертається боком, це перевіряти як regression у `OCVisualEnvironment.cpp` / first-person presentation, а не автоматично списувати на стару локальну гілку.
